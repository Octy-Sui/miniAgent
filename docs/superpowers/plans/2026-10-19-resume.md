# Resume Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现同主机 Local / Docker 原 Workspace 的安全跨进程 Resume，保留已确认进度、冻结定义与计量，并拒绝未知副作用重放。

**Architecture:** Application 持有 Run 文件锁并编排只读预检、恢复事务和原 Workspace attach；Runtime 的 run / resume 汇合到共用 phase dispatch。State 保存唯一业务进度，Journal 通过 SQLite CAS 原子提交事实；Workspace observer、Docker helper / supervisor 和 evaluator 提供可持久化的执行与收尾证据。Diagnostic finalization 只追加事件，不创建业务恢复游标。

**Tech Stack:** Python 3.13.x、Pydantic 2、Typer、asyncio、SQLite、pytest、Git、POSIX flock / process groups；新增宿主依赖 psutil、docker Python SDK。

**Spec:** [需求 D](../specs/2026-10-14-resume-design.md)、[架构 A](../specs/2026-10-14-resume-architecture.md)、[测试分析 TA](../specs/2026-10-14-resume-test-analysis.md)、[测试设计 TD](../specs/2026-10-14-resume-test-design.md)。采用 2026-10-19 工作区版本；代码基线 `e228f70`。另参照 [测试审计](../specs/2026-10-14-resume-test-strategy-audit.md) 的 F1–F5；修订尚不代表审计关闭或测试通过。

## Global Constraints

- “首版目标 macOS / Linux”；“本地主机 POSIX 文件系统”；不支持 Windows、NFS、多主机、数据库硬链接别名或运行中替换数据库。
- “同主机 Local 与 Docker 均支持续跑；Local 接回原目录，Docker 接回原容器。”
- “不创建、读取或恢复 Workspace checkpoint”；保留已有 checkpoint / recover / restore API 的其他调用者契约。
- “无 force、自动重放或人工认领入口”；shell 和第三方工具的未知结果默认拒绝。
- “SQLite schema v3、Run / Snapshot envelope v3、recovery context v2”；直接修改 `001_initial.sql`，不迁移、不兼容、不自动重建旧库。
- “phase + tool_batch.next_index 是唯一 dispatch 依据”；RunCursor 仅为强校验的兼容投影。
- “RunRecord.state 是执行进度的唯一恢复来源”；不能用较旧 Snapshot 回退进度。
- “保持 RunResult 仅表示终态”；新增 RunSuspension，库 CancellationToken 仍表示 CANCELLED。
- “新增、冻结的 30 秒总预算”，覆盖暂停收尾、提交及诊断；不按阶段刷新。
- “resume_attempts 仅累计真实 ResumeStarted”；没有次数上限；每条 resume 命令只发起一次恢复流程。
- “原镜像尚不存在也直接报 EVALUATION_IMAGE_UNAVAILABLE”；allow_image_pull=True 也不拉取、不创建 Workspace / Run。
- “凭据、TLS 私钥内容、环境快照不落库”；冻结绝对路径、原 pricing 内容和两个 Docker 连接身份。
- 不引入通用 RecoveryController、第二套 loop、事件重放引擎、GC、终态 repair、token/cost budget 引擎或 Trace export。
- 遵循根 `AGENTS.md`：不改 README；Python 改动只对相关文件运行 Ruff；真实行为优先，不 mock 项目内部实现。

## Review Focus

1. 提交已应用但调用者未收到确认：存活调用者必须自行退出且不再 attach、dispatch、导出或清理；Task 24 的 G3-E/U 测试固定此行为。
2. helper 已获 start 许可但远端暂时未运行：helper 退出和 Running=false 仍不足以排除延迟 start；Task 11 / 23 覆盖，无安全证据就 busy。
3. 新进程缺少执行身份、PID 被复用或只有主进程退出：不得猜测整组结束或杀邻居；Task 9 / 12 / 22 覆盖。
4. summary / 业务 retry 在反复恢复后余额漂移：必须使用原余额，既不能提前放弃也不能重置；Task 15 固定 2 / 1 / 0 次 summary 和唯一业务 retry。
5. 终态后或暂停后的 diagnostic 遗留执行：业务 State / Snapshot 必须不变，暂停 Run 下一次恢复须检查其发令可能性；Task 25 覆盖。

## 执行约定与范围

这是一个恢复协议，存储、执行监督和评估之间有共同提交边界，不能把 Local-only 或无 Docker helper 的中间版本称为功能完成。因此保留一个总计划，按下表交付；不拆成互相复制协议的独立子项目。每个 Task 有自己的可测试产物和提交，不要求每个中间提交已经提供完整 CLI Resume。

只执行分配的 Task 及其测试，不顺手实现后续 Task。一个 Task 的 **Interfaces** 与下文公共契约一起构成给低阶模型的输入；不得自行换名、修改版本、增加 fallback 或放宽 oracle。若当前代码位置因前序提交移动，按表中的符号定位，不依赖旧行号。实现不能满足既定接口时，先报告冲突及证据，由计划负责人修订接口，再继续。

测试步骤里的 Python 是指定测试函数的断言核心，局部变量的构造在紧邻文字中规定；执行者须补齐 setup 和调用。它们不是另一个测试框架，也不允许创建未定义的“万能 case runner”。复用现有 `submission_case`、`prepared_bundle` 和实际公开 API；需要跨进程屏障时才引入下文列出的公共测试支持。

## 测试证据约定

- TD 的 `TC-Ux-yy`、TA、R 和 AC ID 全部保留；用 pytest node docstring 标注 TC；不同变体用参数 ID。一个 TC 可在组件和 acceptance 各有证据，但不能把组件 stub 通过替代真实后盾。
- `tests/resume_support.py` 在 Task 6 建立 `StoreBoundary`：委托真实 RuntimeStore 的 create/commit/get/查询，在公开返回边界用 pipe 握手；仅支持 `pause_after_commit`、`applied_then_error`、`not_dispatched_then_error` 三种单次动作。最后两种统一向活调用者抛 `RunPersistenceError`，保存真实分支给监督者，调用者不可获知分支。其余操作原样委托；不用该适配器模拟 SQLite 回滚。
