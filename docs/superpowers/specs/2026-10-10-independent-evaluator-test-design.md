**U4：唯一提交状态**

状态：`N` 未尝试，`P` 提交成功，`E` 空 patch，`F` 提交失败。以下状态名对应 A§7，不新增“提交中／已取消”等未定义状态。

| 状态＼事件 | 正式提交 | Application finalization | 读取提交状态 |
|---|---|---|---|
| N | 非空成功→P；空→E；错误→F | 仅诊断提交，按结果→P/E/F | N，不能创建 submission_id |
| P | 不得再次导出／登记；返回形式 Q-7 | 保持 P，复用 ref | P，身份不变 |
| E | 不得再次尝试；返回形式 Q-7 | 保持 E，不补交 | E，身份不变 |
| F | 不得自动重试；返回形式 Q-7 | 保持 F，不补交 | F，身份不变 |

转换清单：

- T1–T3：N 正式提交 → P/E/F。
- T4–T6：N 诊断提交 → P/E/F。
- T7–T9：P/E/F finalization → 原状态。
- T10–T13：N/P/E/F 读取状态 → 原状态。
- I1–I3：P/E/F 再次正式提交 → 禁止再次导出或登记，既有状态和身份不变；调用返回形式按 Q-7 DEFER。

覆盖目标分别为 13 个已定义有效转换和 3 个明确禁止的重复提交动作。重复提交的返回值/异常未定，不妨碍验证无新提交副作用；不把这些动作混入有效转换分母。

| 路径／用例 | 操作 | Covers | 逐步预期 | Trace |
|---|---|---|---|---|
| TC-U4-01 | 正式提交 P → 读状态 → 修改 Workspace → finalization | T1、T11、T7 | 提交有稳定 submission_id；最终 ref 和 bytes 仍是原提交；不二次导出 | TA-07 |
| TC-U4-02 | 空字符串提交 → 读状态 → finalization | T2、T12、T8 | E；`EMPTY_PATCH`；无 attempt；不再导出 | TA-07 |
| TC-U4-03 | 分别导出失败、登记失败 → 读状态 → finalization | T3、T13、T9 | F；具体错误；无 attempt、无自动重试 | TA-07 |
| TC-U4-04 | 模型提前失败 → 非空诊断导出 | T4 | patch 标记 diagnostic；有 submission_id，可无 attempt_id | TA-07、09 |
| TC-U4-05 | 模型提前失败 → 空诊断导出 | T5 | 无非空 patch；不再尝试 | TA-07 |
| TC-U4-06 | 模型提前失败 → 诊断导出失败 | T6 | 原模型失败保持；补充 finalization 诊断 | TA-07 |
| TC-U4-07 | 未提交时读取状态 | T10 | 保持 N；不创建提交身份 | TA-09 |
| TC-U4-08 | 非空仅空格候选 | 非空分类 | 不报 `EMPTY_PATCH`；实际是否适用由 harness 判断 | TA-07 |
| TC-U4-09 | patch 发布完成、内存 ref 保存前取消；随后汇总 | 发布竞争路径 | 按 submission_id 恢复已验证 manifest；唯一 patch；不重导出 | TA-09 |
| TC-U4-10 | patch 尚未确认发布时取消 | 发布竞争路径 | 不虚构 ref；保留 Workspace、诊断；不重试 | TA-09 |
| TC-U4-11 | N 正式提交成功到 P；修改 Workspace 后再次显式正式提交，再读取状态 | T1、I1 | 第二次调用不重新导出或登记；仍为 P，submission_id、ref、交付 bytes 不变；只有首次 patch record | TA-07、09 |
| TC-U4-12 | N 空提交到 E；在 Workspace 增加可导出的改动后再次显式正式提交 | T2、I2 | 仍为 E，submission_id 不变；无新导出、patch record 或 harness attempt；第二次调用返回形式按 Q-7 DEFER | TA-07 |

**U10：配置与时间边界**

采用 3 值 BVA。整数步长为 1；浮点时限使用测试配置步长 `δ=0.1s`，仅作为选样尺度，不表示产品精度要求。

| 边界 | 有效分区 | 测试值 | 各值预期 |
|---|---|---|---|
| 测试超时正整数 | `t≥1` | -1、0、1、2 | 前两者拒绝；后两者接受 |
